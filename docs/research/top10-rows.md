# Ranked Top 10 artwork

## Phase 2 implementation (2026-11-14)

Coordinator approved Phase 2. `rankedTop10` is an additive collection setting and a three-state Home Designer row override (Default/On/Off). Final authorized row order determines 1..10; ranked rows have no continuation. Vela carries the neutral flag through row snapshots for native `presentation: "ranked"` rendering.

Plex advertises `Meta.DisplayImage=imageType:coverArt` for each ranked native movie/show shelf and supplies both a wide `Image.coverArt` and portrait `thumb`/`Image.coverPoster`. This is wide-first capability negotiation: every client gets the hint, clients consuming it can draw wide, and those ignoring it have a usable portrait. No item types, Continue Watching identities, or playback keys are fabricated.

Fixed 500x750 portrait and 960x540 wide composites are made only on image read. The portrait has a full-card blurred/darkened poster vignette, a 36% left strip, and a sharp 64%-width bottom-right poster drawn over the numeral edge. Numeral glyph proportions are preserved; 10 scales down to fit. This replaces the earlier 78% strip experiment. JPEG gutters use near-black; no new cache format is introduced.

Image variants wrap an authorized source descriptor; reads re-enumerate its underlying poster under current viewer policy before cache lookup. Jellyfin/Emby sign per-row descriptors without per-title grant writes; changing rank changes the tag, while ordinary search/detail tags remain unranked. Short-tag recovery with the persisted node key enumerates only the bounded 30 rank/aspect/image-kind variants for one poster. Visibility and revocation still apply.

## Decision supported by the evidence

Keep native movie/show types. Ship portrait composites as the fallback. Plex Web 4.163.0 has a source-traced candidate for **wide movie/show shelves** using `Meta.DisplayImage` plus `Image[type=coverArt]`; verify this on an Ether mock server before enabling it. A landscape `thumb` alone does not control the card geometry. Do not infer support on other clients from Web.

The closed-client entries below are deliberately marked unproven. There is no defensible proof that Apple TV, iOS, Roku or LG/Samsung accept an arbitrary server-defined wide movie/show shelf. Their ordinary native shelves remain usable through portrait composites. This is a conservative delivery choice, not a claim that wide presentation is impossible.

## Jellyfin / Emby / Vela

Jellyfin DTOs expose `ImageTags.Primary`, `ImageTags.Thumb`, `BackdropImageTags` and `PrimaryImageAspectRatio`; serve matching `/Items/{id}/Images/{type}` endpoints. A landscape primary should truthfully advertise 16/9. `Thumb` is a landscape card image, whereas `Backdrop` is also used for screen backgrounds. Neither forces every client shelf wide.

Jellyfin Web commit `e9c5a40cdfab49ecffc5b572dc9f9c64f8e30fed`:

- [recentlyAdded.ts](https://github.com/jellyfin/jellyfin-web/blob/e9c5a40cdfab49ecffc5b572dc9f9c64f8e30fed/src/components/homesections/sections/recentlyAdded.ts) fixes movie/tvshow latest rows to portrait and disables preferThumb for them. A primary ratio cannot override that explicit shape.
- [cardBuilder.js](https://github.com/jellyfin/jellyfin-web/blob/e9c5a40cdfab49ecffc5b572dc9f9c64f8e30fed/src/components/cardbuilder/cardBuilder.js), `setCardData`: auto-shaped rows use primary aspect ratio; >=1.33 selects backdrop shape, >=3 banner, >0.8 square. `preferThumb=auto` follows the resolved backdrop shape. Thus wide primary/Thumb works in suitable auto/thumb views, not universally on Home.
- Standard image API has no arbitrary per-row image variant token. Phase 2 must use a signed, authorized row-scoped image descriptor/path supported by Ether's adapter; changing a title's global Primary or Thumb would leak rankings into details/search. Client caching keyed solely by item ID/image type may prevent row-local substitution and must be tested.

Emby exposes the analogous image types and primary ratio ([official library API](https://dev.emby.media/reference/RestAPI/LibraryService.html)). Read-only local reference server's `dashboard-ui/modules/cardbuilder/cardbuilder.js`, SHA256 `5293e5d00609afc8f80f1e841e044745a4b7b96cf8f3dfcfe1a17ecaa82d9c16`, resolves auto shape through imagehelper and switches `preferThumb=auto` according to backdrop/fourThree shape. This proves a client-side choice, not server control of every Home row. Use portrait fallback until the target row/client is proven; preserve real item Type and globally unranked image types.

Vela coordination with `thr_ucqnvk37fq` and protocol owner `thr_tgszknwfsb`: current Row has `id`, `name`, `purpose`, `receiptToken`, optional `style`/`previewOnFocus`, `items`, optional `nextCursor`, and `continuation`. RowEntry has stable `id`/`receiptToken` plus its title/channel/etc. union. No native Top 10 hint exists yet. Proposed additive Phase 2 seam: `Row.presentation?: "ranked"`, optional `cardAspect?: "portrait" | "landscape"`. Rank = one-based final `items` position, max 10; preserve IDs and receipts. Native skins should draw rank without baked art. Protocol worker is waiting for coordinator approval before editing types.

## Phase 2 cache and scope contract

1. Mark collection/row ranked; cap final authorized, deduplicated row to 10 **after** ordinary row ordering. Assign ranks after policy filtering so gaps do not expose hidden titles. Preserve final order and item identity. Define continuation so a later page cannot restart rank 1 or display rank 11.
2. Construct image descriptors/URLs only during browse. Rank belongs to the row/card presentation, not `core.Title`, not global poster metadata, not provider artwork selection.
3. Render only when the client requests an image. Reuse `overlays.posterCache.get`'s bounded memory/durable disk cache, detached singleflight and render concurrency limits; do not introduce a second unbounded cache or background warm-up. No eager catalogue work.
4. Extend the visual key with **rank 1..10, portrait/wide aspect, dimensions, renderer/font version, source poster content/version, existing localized/personalized poster selection and overlay pixel inputs**. A title at rank 1 and rank 7 must have distinct URLs/cache entries; identical pixels across rows can share bytes. Do not put raw viewer identity in a pixel key; authorization still runs on every image request, before a cache hit.
5. Preserve durable restart reuse and existing disk byte budgets. Never cache a temporary unavailable-source placeholder as the definitive real composite. Bound decode pixels as in `renderPoster` and clamp output dimensions. Check cancellation, reject invalid rank/aspect, avoid arbitrary image URLs bypassing the shared authorized artwork pipeline.
6. PNG transparency follows the client's dark shelf. Existing generated overlay cache is JPEG-oriented: choose either an explicit PNG variant/content type/suffix path, or flatten once onto near-black and include that encoding/background in the visual key. Never save PNG under the existing JPEG return contract.
