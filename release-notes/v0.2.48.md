This release improves library setup, playback reliability, owner-console security,
watchlist monitoring and server maintenance.

## New and improved

- **Name your libraries:** rename Movies and TV Shows in **General → Server**.
  Existing library identities and section IDs stay the same.
- **New-episode alerts:** monitored shows and seasons are checked for their newest
  aired regular episode after initial availability. When a playable release is
  found, Ether can notify you and prewarm it. Specials no longer displace a
  regular pilot. Episode alerts use durable deduplication with Ether's notifier.
- **Backup and update notifications:** scheduled backup failures can send an
  alert, and newly discovered Ether versions produce the existing
  `update.available` event. Failed backup attempts back off instead of repeatedly
  taking a snapshot every minute.
- **Cache free-space reserve:** automatic eviction also aims to leave the smaller
  of 10 GiB or 5% of the cache volume free, including shared caches. Pinned and
  actively protected releases remain protected, so the reserve cannot be
  guaranteed when they occupy the remaining space.
- **Clearer connectivity:** the dashboard displays HTTPS addresses reported by
  Plex discovery, labels local, remote and relay connections, and lets you copy
  the complete address. Registration addresses are explained separately.
- **Honest health status:** a loaded but unverified certificate no longer leaves
  the header saying “Checking” forever or makes Overview claim everything is
  healthy. Certificate expiration and verification are distinguished.

## Playback and compatibility fixes

- Direct Stream sessions keep their adaptive fallbacks unless you turn
  **Adaptive bitrate ladder · Direct Stream** off under Advanced. Leaving
  it off advertises only the copy primary. Existing servers keep the
  fallbacks; this does not change the default.
- Editing a quality profile's limits, codecs, or sources forgets the
  remembered release for that profile, so the next play follows the edited
  profile. The same profile still matches across clients. A profile name
  may contain `|`. This is one way a remembered release could ignore an
  edit; it does not by itself resolve every 4K playback report.

- Fix Plex Watchlist imports when Discover returns both a `guid` string and a
  `Guid` external-ID array (#139).
- Start lazy HLS renditions for ranged initialization requests instead of
  returning 503 (#140). DASH range probes retain their existing behavior.
- Pass the required target bitrate to VAAPI QVBR quality mode, avoiding the
  missing-bitrate encoder failure that can trigger CPU fallback (#135).
- Distinguish client and quality-profile resolution ceilings in release-history
  rejection reasons (#131). This improves diagnosis; it does not override device
  capabilities or force 4K/HDR playback.
- Keep local-file thumbnail inputs local, avoid duplicate SDH subtitle labels,
  and prevent TMDB episode-order wiring from breaking local spike-mode details
  (#129, #130, #132).
- Retain conservative browser HDR capability handling with additional regression
  coverage (#136); this release does not enable HDR for every browser.

## Security and reliability

- The owner console now stores a revocable Ether session instead of the owner's
  Plex account token. Sessions are checked against current ownership, expire,
  and are revoked on sign-out. A content security policy limits console scripts.
- Harden sensitive query-parameter redaction in logs and enforce the concurrent
  upstream authentication-validation limit atomically.
- **Download logs** from the owner console's Logs page. The file is this node's
  logs with known credential fields removed, for a bug report. Review it before
  sharing: unrecognized secrets may remain. Settings and the database are not
  included.
- Cluster nodes wait for their own durable startup heartbeat before serving.
  Ownership checks prevent stale processes from overwriting a changed registry
  row. A resumed stale process detects ownership loss on its heartbeat interval;
  this is not a fence on every request.
- Future releases require written, version-specific release notes before
  publication. Historical notes are now stored in the repository too.

## After upgrading

- **Sign in to the owner console again.** The old stored Plex token is removed
  when the updated console loads. This does not unclaim the server or erase its
  configuration. Existing owner-token API automation remains supported.
- Select the desired events on your notification channels to receive backup,
  update and watchlist alerts. Watchlist monitoring and prewarming remain
  configurable.
- Reload an already-open dashboard to use the updated interface.
- **SQLite keeps three pre-migration snapshot sets.** Before migrations, Ether
  writes `ether.db.pre-migrate.bak` and stores the matching `config.json` and
  `.credentials-key`, as they were before that start, in
  `ether.db.pre-migrate.bak.files/`. The three newest sets are kept
  (`.pre-migrate.bak`, `.1`, and `.2`), including each set's companion
  directory. If a companion file cannot be read, Ether warns that the database
  snapshot alone may not restore settings and credentials. To roll back by
  hand, stop Ether, install the previous version, and replace `ether.db`,
  `config.json`, and `.credentials-key` with one set's copies.
- **A schema newer than this binary does not block startup.** An older build
  keeps running on a database a newer build already migrated, and logs a
  warning naming the newer components. On SQLite that warning also names the
  newest snapshot when the file is present. That is what lets an updater
  rollback and a mixed-version cluster keep serving.
- **PostgreSQL gets no pre-upgrade snapshot.** Use scheduled backups for that
  database. Rolling back a release never restores a snapshot automatically.

## Docker

The Dockerfiles use Debian 13 (trixie) so the image ships libva 2.22, which
exports `vaMapBuffer2`. The bundled Jellyfin FFmpeg 8.1.3 resolves that symbol
with `dlsym`. An arm64 image from this tree booted, ran as uid/gid 999, loaded
FFmpeg 8.1.3-Jellyfin against libva 2.22.0-3, and completed a software encode
with no GPU attached. The same ffmpeg against a Bookworm libva 2.17.0-1
userspace fails `dlsym` with `undefined symbol: vaMapBuffer2`. On amd64, the
Trixie libva2 package 2.22.0-3 exports the symbol and `dlsym` succeeds. An
amd64 Ether image boot is still outstanding: the remote containerd snapshotter
has no free space. The account in the image is still uid/gid 999. amd64 images
still include Debian's Intel iHD and i965 VAAPI drivers and the oneVPL runtime
`libmfx-gen1.2`. NVIDIA and Mesa packaging are unchanged. This does not add
the legacy Intel Media SDK runtime. Quick Sync error -22 on HD Graphics 620
and high CPU during copy/remux remain unverified. No live GPU result is claimed.

## Known limits

The connectivity and health changes do not establish a fix for every remote
playback or certificate report. The HLS repair has offline regression coverage;
the contributor reports Plezy recovery, but no new live-client test is claimed
here. No live VAAPI, Quick Sync, or browser HDR test is claimed. Quick Sync
error -22 on HD Graphics 620 and high CPU during copy/remux are separate
and not fixed here. This release still serves Plex clients; Prism/Jellyfin
client support is not included.
