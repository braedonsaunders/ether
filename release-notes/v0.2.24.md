# Ether 0.2.24

- Fixed missing owner feature UUIDs in responses to Plex clients, addressing the Remote Watch Pass entitlement mismatch reported by shared iOS and Apple TV users whose server owner has Plex Pass (#19). Ether fetches the authenticated server feature list on claim, at startup, and during the six-hour refresh, and publishes UUIDs alongside existing feature names.
- Setup now explicitly tells you when changing the media-cache folder requires restarting Ether or its container (#20). Media segments use the configured folder; artwork remains under the configuration folder. Existing cached files are not moved automatically.
- Enforced the configured minimum resolution for releases with a known resolution. The default 4K profile still allows 1080p–2160p; set its minimum to 2160p for 4K-only automatic selection. Explicit release choices retain their override behavior.
- Fixed Ether Posters returning 404 when Plex requests artwork through its image-resizing endpoint.
- Fixed uncached TorBox releases being discarded when Cached Only is disabled, and queue uncached downloads when playback is requested (#17).
- Improved Usenet BODY request scheduling to avoid serial waits during pipelined reads.

Existing installations fetch owner feature UUIDs during startup after updating; re-claiming is unnecessary. Fully quit and reopen the Plex client if it retains old server capabilities. A failed refresh preserves the last verified feature snapshot and retries.

If you changed the media-cache folder during setup, restart Ether or the container to apply it. For `/cache`, media segments are stored in `/cache/data`; `/config/cache/images`, `posters`, and `overlays` are separate artwork caches.

This release includes the fixes from the unpublished v0.2.23 draft.
